# nupdf

A PDF engine for AI agents, in Rust: the `nupdf` library (`crates/nupdf`), the `nupdf` command and MCP server (`crates/nupdf-cli`), and dev tooling run as `cargo xtask` (`xtask`). These are the instructions for anyone changing it, person or agent.

MuPDF is the behavioural reference: by default nupdf does what a pinned MuPDF build does, checked file by file. Before changing a subsystem, read its entry in `docs/ARCHITECTURE.md` (which MuPDF file it follows) and the decisions it cites in `docs/DECISIONS.md`. Open work is in `docs/PLAN.md`.

## Commands

- Build and test: `cargo test --workspace`, then `cargo test --workspace -- --ignored` (needs the reference build).
- Lint: `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all`, `cargo deny check`.
- The reference: `cargo xtask oracle build` builds the pinned MuPDF into `target/oracle/mupdf-<version>/`. Its `source/` tree is what to read for how MuPDF does something.
- Parity: `cargo xtask harness [--tier smoke|standard|wild] [--check NAME] [--sample N] [--update-baseline]` compares nupdf with the reference. `cargo xtask triage FILE --page N` diffs one page.
- Corpora: `corpus/smoke` is generated by `cargo xtask fixtures`; never edit those files by hand. The larger tiers are fetched with `cargo xtask corpus fetch <name>` into `~/.cache/nupdf/corpus`.
- Crashes: `cargo xtask crashes --tier wild [--resume] [--summary]` runs every command on every file of a tier.
- Speed: `cargo xtask bench [--tier T] [--sample N] [--runs N] [--against pdf_oxide|engines]` ([BENCHMARKS](docs/BENCHMARKS.md)).
- Reading order: `cargo xtask reading-order` scores `--options reading-order` against the hand-labelled pages in `corpus/reading-order`.
- Fuzzing: `cargo +nightly fuzz run -O <target>`, one target per parser surface in `fuzz/fuzz_targets/`.
- Coverage: `cargo llvm-cov --workspace --summary-only --ignore-filename-regex '(nupdf-cli|xtask|fuzz)/'` (at least 90% of the library).
- The agent eval: `eval/` ([its report](eval/REPORT.md) says how to rerun it). Its runs start paid model sessions, so run it only when asked.

## Rules

- **Tests first.** A change comes with the tests that show it works; a bug fix with one that failed before it. Prefer real files and real dependencies to mocks.
- **Input is hostile.** No `unsafe` (the workspace forbids it). No `unwrap`, `expect` or `panic!` on a path that touches input. Every loop and recursion over a file's contents is bounded through `Limits` or an explicit cap.
- **The default is the reference's behaviour.** Anything better (a stricter parse, a better reading order) is an opt-in option, recorded in `docs/DECISIONS.md` (D5).
- **Parity is measured, and only goes up.** Run the harness checks a change can affect. Update a baseline only when results improved, never to hide a regression.
- **Derived code says where it comes from.** A module that follows a MuPDF file carries the header in `crates/nupdf/src/header.rs` (SPDX line, our copyright, "Derived from MuPDF <path>", Artifex's copyright) and gets a row in the module map in `docs/ARCHITECTURE.md`. Third-party code carried in the tree is listed in `NOTICE.md`.
- **Every command answers with a versioned report**: `schema`, `doc_id` and `diagnostics` ([AGENT-INTERFACE](docs/AGENT-INTERFACE.md)). New warnings get stable dotted codes. A change to a report's shape follows [SCHEMA-CHANGELOG](docs/SCHEMA-CHANGELOG.md).
- **A new parser surface gets a fuzz target** in the same change.
- **Dependencies are pure Rust**, with licences on the `deny.toml` allow-list.
- **Docs follow the code.** `nupdf guide --skill > skills/nupdf/SKILL.md` after changing the guide (a test checks they match). Numbers in the docs come from a run, with the command that made them.

## Changes

- Everything reaches `main` through a pull request; `main` is protected and needs the `check`, `deny` and `smoke` jobs to pass on a branch that is up to date with it.
- Small commits whose messages say why. Tick the matching box in `docs/PLAN.md` in the commit that finishes the work.
- Releases follow [RELEASING](docs/RELEASING.md); publishing is done by hand.
